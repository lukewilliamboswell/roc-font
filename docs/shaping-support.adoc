= Shaping models and evidence

This matrix separates model selection from evidence for particular fonts.
Selection follows the pinned HarfBuzz 14.6.0 OpenType models; it does not
promise agreement for every font using that script. Cached cases compare
glyphs, advances, offsets, original clusters and, where requested, unsafe
flags through the native driver importing the served package bundle.
Record counts describe the checked-in matrices, including any read cases;
the conformance gate establishes agreement for the current package build.

== Historical foundation snapshot

The 2026-10-28 native replay on foundation commit `39b66c3` recorded 7,116
gating cases: 7,098 agreements, 16 declared known differences and two
unsupported cases, with no unexpected failure. The separately scored
HarfBuzz in-house corpus recorded 4,935 agreements, 107 differences,
73 unsupported and 59 unavailable-font skips among 5,174 cases. This is
evidence for those cases, not a percentage of HarfBuzz's feature surface.
The AOTS and text-rendering-tests scored suites were not imported here.

Of the 107 in-house differences, 37 reject the font at reading. The
remaining 70 include unsupported AAT behavior, legacy kerning formats,
`gvar`-only advance changes, duplicate variation-axis tags, legacy Zawgyi,
and reference-specific handling of two Courier New fonts with problematic
GDEF classifications. The 58 cases filed under `macos` are therefore not
all AAT gaps. No unclassified GPOS lookup defect was identified in this
replay; this does not prove that every font or lookup combination agrees.

== Model selection

The caller supplies one script run, its script/language and direction.
The selected font's OpenType script matters as well as the Unicode script.
The implementation is in link:../package/Shaper.roc[Shaper] and
link:../package/ShaperUse.roc[ShaperUse].

[cols="1,3",options="header"]
|===
|Script/model |Selection and limits
|Default |Other scripts use the default OpenType pipeline. This is not a
claim that their script-specific requirements are implemented.
|Hebrew (`Hebr`) |Default pipeline with Hebrew normalization/positioning
rules. There is no dedicated two-family Hebrew oracle matrix here;
public missing-glyph/direction tests do not establish Hebrew typography.
|Arabic (`Arab`), Syriac (`Syrc`) |Arabic joining and staged features.
Syriac selects this model unless the chosen font script is `DFLT`.
Presentation-form fallback and `stch` have dedicated additional matrices
replayed through the public native driver.
|Hangul (`Hang`) |Jamo composition/decomposition, tone handling and Hangul
feature masks, including missing-jamo/dotted-circle boundaries.
|Thai (`Thai`), Lao (`Laoo`) |Script preprocessing; Thai also has legacy
Windows/Macintosh shaping when the selected script is not `thai`.
|Nine Indic scripts below |Indic model unless the selected script is
`DFLT`, `latn` or a version-3 tag. Version-3 selection uses USE instead.
Modern version-2 Noto fonts do not prove every legacy-tag path.
|Khmer (`Khmr`) |Khmer syllables, coeng/matra reorder and staged features.
|Myanmar (`Mymr`) |Modern Myanmar unless the selected script is `DFLT`,
`latn` or legacy `mymr`. These use the default model. Zawgyi (`Qaag`) is
not claimed by the modern Unicode Myanmar implementation.
|USE |The 91 scripts listed below, plus Indic version-3 selection, unless
the chosen font script is `DFLT` or `latn`. Joining scripts use the Arabic
joining machine within USE's feature order; they are not the Arabic model.
|===

All these runs reported zero leaked allocations. Requested bytes and peak
live bytes are unavailable in roc-fuzz 0.4.3; RSS is not a substitute.
The USE consumer checks script, UTF-8 length and an input checksum against
the comparator. Its link:../tests/fonts/complex/use-before-checked-measurements.json[pre-model baseline]
has incomplete shaping semantics and cannot establish an equivalent-output speedup.
The separate link:../bench/records/scripts/default-queries.json[default-path record]
uses system HarfBuzz 13.2.1 and must not be mixed with the 14.6.0 ratios.

== Practical boundaries

The development branch extends the foundation snapshot above. Dedicated
feature proofs are retained beside their fixtures; they do not replace the
final shared integration gate.

* CFF/CFF2 paths include cubic curves, subroutines, CID fonts and variable
  blends. link:../tests/fonts/cff/README.md[The CFF proof] distinguishes
  normative and FreeType comparisons from three HarfBuzz draw discrepancies.
* Variable metrics include `gvar` phantom points when `HVAR`/`VVAR` are
  absent; `avar` v2 cross-axis remapping is implemented. See
  link:../tests/fonts/variation-complete/[the variation evidence].
* Vertical shaping includes top-to-bottom and bottom-to-top runs,
  substitutions, positioning, vertical metrics and origins. The
  link:../tests/fonts/vertical/[vertical matrices] include Japanese and
  Mongolian fonts and two declared VORG/TrueType policy differences.
* Apple substitution programs include all five modern `morx` and legacy
  `mort` program types. Apple positioning covers `kerx` formats 0/1/2/4/6,
  legacy `kern` formats 0/1/2/3 and size-dependent tracking. Dedicated
  link:../tests/fonts/aat/[modern morphing],
  link:../tests/fonts/aat-mort/[legacy morphing] and
  link:../tests/fonts/aat-position/[positioning] matrices establish those
  cases, with malformed-font, native fuzz and scaling evidence.
* Graphite preparation and execution remain under integration. Small
  original VM controls pass the public native replay, while real-font
  association and collision differences are still being resolved. Four
  real SIL families passing preparation does not establish runtime parity.
  The default HarfBuzz Graphite adapter and the independent Graphite2
  lazy-face API use different preload modes; their evidence is labelled
  separately. Graphite's adapter uses horizontal advances even when the
  caller requests a vertical buffer direction. Set `use_font_programs`
  to false to select the OpenType path, including its vertical metrics.
* WOFF/WOFF2 data needs decompression before this sfnt reader can accept
  the font bytes; container unwrapping remains separate work.
* After work-budget exhaustion, partial progress can differ from HarfBuzz's
  buffer-accounting progress. Explicit stopped-run cases are checked with
  an independent model; completed runs require oracle agreement.
* Legacy kerning follows the selected script's fallback policy. The
  link:../tests/fonts/shaping/kern-policy/kern-cases.jsonc[93-case matrix]
  covers suppression for scripts whose models disable it and retention
  for the default and Hangul models. Forced LTR runs of normally RTL
  scripts still have an observed legacy-kerning offset-side discrepancy.
* Bidi, script-run/grapheme segmentation, line breaking and font fallback
  selection belong to downstream packages. A mixed paragraph needs those
  steps before shaping its runs; these font-local models do not supply them.
* MATH supplies font constants and stretch recipes. Expression parsing,
  mathematical box layout and PDF/SVG output remain consumer work; font
  support alone does not replace a LaTeX pipeline.
