= roc-font 0.1.0-rc3

A release candidate for 0.1.0, with the API 0.1.0 is planned to have.
Since rc2 it acts on consumer feedback: `Font.shape_traced` takes text and
reports budgets, the flag predicates are `is_missing` and
`is_unsafe_to_break`, `Font.Extents` names the glyph box, and planning is
much cheaper (see "Changes since 0.1.0-rc1" below). CI now builds with the
latest Roc nightly. Unless consumers find a problem, 0.1.0 will be this
release under its final name.

The first release of roc-font: read TrueType and OpenType fonts and turn
text into positioned glyphs, in pure Roc, with three fonts built in. It
needs no host, no system fonts and no file access.

== Use this release

[source,roc]
----
app [main!] {
	cli: platform "https://github.com/roc-lang/basic-cli/releases/download/0.26.0/GddgvsGjiNXrHFW6au5i5dUDbTs8FinQdrgE2Gqmw53t.tar.zst",
	font: "{package-url}",
}

import font.Font
----

Build with the latest Roc nightly. The release page lists the nightly
this release was tested with under Compilers. While it is the latest
final release, a daily check builds and runs its examples, unchanged, with
each new nightly; a failure there leads to a patch release. The release also attaches
`roc-font-examples-0.1.0-rc3.zip` (the examples, naming this release, with
the output they were tested to print), the API reference and the manual
as a PDF.

== What it provides

* **Reading fonts.** `Font.from_bytes` reads a TrueType or OpenType font
  file, or one font of a collection, and checks every offset, count and
  length before using it. When a file cannot be used, it reports every
  problem it found, naming the table and byte offset where they help. By
  default reading accepts what browsers accept and reports what it left
  out with `Font.dropped`; `strict: True` rejects a font for any problem,
  for files you will pass on, such as into a PDF. After a successful read,
  every query and every shaping call has a defined result.
* **Font facts, in font units.** Units per em; ascent, descent and line gap
  as browsers take them; cap and x height; underline and strikeout; the
  glyph for each character; each glyph's advance and bounding box; every
  character the font maps; the family name and glyph names.
* **Shaping.** `Font.shape` turns a string into glyph ids, advances, offsets
  and clusters (the UTF-8 byte offset in your text of what each glyph
  draws), with flags marking where breaking a line would mean shaping
  both sides again and which glyphs stand in for characters the font
  lacks.
  `Font.width` is the shaped width. Shaping applies the font's
  substitutions (ligatures, contextual and stylistic alternates, all eight
  substitution lookup types) and its kerning, the browser default features
  unless you choose others, over the whole text or a byte range. You can
  set the script, language, direction and cluster level, and plan once to
  shape many strings.
* **Variable fonts.** `Font.at` moves a font to any weight, width, optical
  size or other axis, named as in CSS. Advances, metrics, kerning and glyph
  boxes follow. `Font.axes`, `Font.instances` and `Font.coordinates`
  describe the font's design space.
* **Three built-in fonts.** `Font.sans` (Inter 4.1), `Font.serif`
  (Merriweather 4.009) and `Font.mono` (Fira Code 6.2), all variable, all
  under the SIL Open Font License 1.1, are read when your program is
  compiled and cost nothing in a program that does not use them. Their
  bytes and licence texts are exposed too, so you can embed the font you
  measured with.

== How closely it matches the references

roc-font is compared with reference implementations through recorded
results, so every check runs without the references installed.

* **Shaping matches HarfBuzz 14.6.0** on the cases every change must pass:
  of 463 recorded cases (HarfBuzz shaping, Chrome widths, OTS reading and
  font facts), 445 agree, 16 are documented differences, 2 use
  options the test driver cannot express yet, and none fail.
* **On HarfBuzz's own test suites**, roc-font's glyphs and positions equal
  HarfBuzz's in 4,087 of the 4,961 in-house cases it runs (82 %); most of
  the 874 differences are in scripts HarfBuzz gives their own shaper
  (Tibetan, Indic, Arabic, Thai). In the text-rendering-tests suite 212 of
  352 agree; most of the 140 differences need Apple's `morx` and `mort`
  tables, which roc-font does not apply, or are fonts OTS refuses.
* **Variable fonts are bit-identical with HarfBuzz.** roc-font repeats
  HarfBuzz's single-precision arithmetic on integers; normalised
  coordinates and advances differed in none of 11,920,275 advances
  compared over grids and random locations of the three built-in fonts.
* **Reading follows OTS**, the font sanitiser Chrome and Firefox load fonts
  through: a font is accepted when OTS 9.3.0 would accept it, and only the
  parts OTS drops (the variation tables as one unit, an unsorted `kern`
  table) are left out. Over 1,278 fonts it refuses exactly the fonts OTS
  refuses, except that it does not require the `OS/2`, `name` and `post`
  tables or outlines to be present.
* **What "accepts what OTS accepts" covers.** It is about damaged tables:
  a table that is present but broken rejects the font exactly when OTS
  would reject it, or is left out exactly as OTS drops it. A *missing*
  optional table is a deliberate divergence: OTS refuses a font without
  `OS/2`, `name` or `post`, while roc-font reads it (metrics then come
  from the horizontal header, and the family and glyph names are
  `Missing`), because metrics-only and subset fonts that leave these out
  are common in tests and tooling.
* **Glyph boxes follow HarfBuzz.** A glyph whose `glyf` entry has no
  contours (a space, or every glyph of a metrics-only subset that keeps
  the header boxes) has no extents: `Font.extents` is `Empty`, as
  HarfBuzz reports zero extents, even when the entry's header stores a
  box. The seed read that header box instead.

== Changes since 0.1.0-rc1

Feedback from package-mermaid and roc-pdf on the release candidate:

* **`Font.shape_traced` takes text and also reports budgets.** It takes
  a `Str`, as `shape_planned` and `shape_checked` do, and returns
  `Try({ run, origins }, [OverBudget({ run, origins, budgets })])`, so a
  caller that needs the run, its origins and its budgets shapes once.
  Where rc1 code passed scalars, pass the text; where it read
  `traced.run` and `traced.origins`, match on `Ok({ run, origins })` (and
  `Err(OverBudget({ run, origins, budgets }))`, which still holds the
  whole text's run).
* **`Font.Extents` names the glyph box**
  (`{ x_min, y_min, x_max, y_max }`); `Font.extents` returns
  `[Extents(Extents), Empty, Unknown]`, the same values as before, so
  matching code is unchanged.
* **Flag predicates follow Roc's naming:** `Font.unsafe_to_break` is now
  `Font.is_unsafe_to_break`, and `Font.missing` is `Font.is_missing`.
* **Origins credit `liga` first.** A substitution several features list
  (fonts often list the same ligatures under `liga` and `clig`) is
  credited to one that is on for the glyph: `liga` first, then the other
  features shaping applies by default, then features the options turned
  on, each group in tag order. rc1 used tag order alone, which reported
  such ligatures as `clig`. Origins carry no lookup index or input
  glyphs; this is now documented on `Font.GlyphOrigin`.
* **Text as UTF-8 bytes** is documented: `Str.from_utf8` then
  `Font.shape_planned`, or decode yourself and pass each scalar with its
  byte offset to `Font.shape_scalars`.
* **Planning is cheaper.** `Font.plan` (and so `Font.shape` and
  `Font.width`, which plan per call) costs 9 allocations for Inter
  instead of 121, and 14 instead of 767 with a language set, and about a
  fifth of the instructions. Shaping short labels with a plan per label
  takes about 7.5 µs per label instead of 17.7 µs on the machine the
  benchmarks ran on; with one plan for all, about 3.4 µs.

== Known limits

* **Complex scripts use the default shaper.** Scripts that need their own
  shaper (Arabic joining, the Indic scripts, Khmer, Myanmar, Thai, Hangul
  and the Universal Shaping Engine scripts) are shaped as HarfBuzz's
  default shaper shapes them, which is not how they should look. Hebrew
  has its shaper.
* **Positioning is kerning only.** Pair adjustment and the TrueType `kern`
  table are applied; single adjustment, cursive attachment, mark
  attachment and contextual positioning lookups are not yet.
* **No CFF outlines.** Fonts with `CFF` or `CFF2` outlines are read and
  shaped, but their outlines are not, so `Font.extents` is `Unknown` for
  their glyphs.
* **No Apple Advanced Typography.** The `morx`, `mort` and `trak` tables
  are not applied.
* **`avar` version 2 is not supported**: such a font reads as its default
  design, with the variation space left out and reported by `Font.dropped`.
* **Plain font files only.** WOFF and WOFF2 files must be decompressed
  first, and text runs horizontally, left to right or right to left.
* roc-font does not detect scripts or reorder mixed-direction paragraphs.
  Split text into runs of one script and direction first, for example with
  the `unicode` package.
