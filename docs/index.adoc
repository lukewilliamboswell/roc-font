[.lead]
roc-font reads font files and turns text into positioned glyphs, in pure
Roc. Give it the bytes of a TrueType or OpenType font and it returns font
facts in font units (metrics, the glyph for each character, advances,
extents) and the glyphs a run of text becomes after the font's default
ligatures and kerning. It needs no host, no system fonts and no file
access, so it behaves the same in an application, a package, a test or a
browser.

[#use-roc-font]
== Use roc-font

roc-font is for programs that need to know how much room text takes, or
which glyphs to draw for it, without asking an operating system: layout
engines, PDF writers, diagram renderers and games.

You provide:

* the bytes of a font file, which you load however your platform allows;
* the text to measure or shape.

roc-font returns:

* font-wide facts such as units per em, ascent and descent;
* the glyph for each Unicode code point, and each glyph's advance and
  outline extent;
* the glyphs of a run after the font's default substitutions, with
  clusters pointing back into your text, and the kerning between them.

Every result is in font units. Divide by the font's units per em and
multiply by the font size to get the size you draw at; rounding to a pixel
grid is yours to choose, because every renderer rounds differently.

Reading is the only step that can fail. Font bytes are treated as
untrusted: a file that cannot be used is reported with every problem
found, and every query on a font that was read successfully has a defined
result, including empty text and missing glyphs.

roc-font does not rasterise, hint, wrap lines, choose fallback fonts or find
fonts on the system. Those belong to the program that uses it. Unicode text
segmentation (graphemes, line breaks, bidirectional text, script runs) is
left to a Unicode package.

[#getting-started]
=== Getting started

Add roc-font to your application's header, with the bundle URL that the
release notes of your chosen release give in place of `package-url` below,
and use the latest Roc nightly (the notes name the nightly each release was
tested with, and the latest final release is checked against every new
nightly):

[source,roc]
----
app [main!] {
	cli: platform "https://github.com/roc-lang/basic-cli/releases/download/0.26.0/GddgvsGjiNXrHFW6au5i5dUDbTs8FinQdrgE2Gqmw53t.tar.zst",
	font: "{package-url}",
}

import font.Font
----

The quickest start is a built-in font. This program, `examples/measure.roc`
in the repository, measures a string with `Font.sans` (Inter) and scales the
result to pixels. In the repository the examples name the package by its
path, `../package/main.roc`; your application names the release URL.

[source,roc]
----
include::../examples/measure.roc[]
----

It prints:

[source,text]
----
"Hello, world!" is 12111 font units wide (2048 to the em),
which is 94.6171875 px at 16 px.
----

Three habits cover most uses:

* *Read once, use many times.* `Font.from_bytes` checks a font file and is
  the only call that can fail; keep the `Font` it returns and measure and
  shape with it as often as you like. `Font.sans`, `Font.serif` and
  `Font.mono` are already read.
* *Work in font units.* Divide by `Font.units_per_em` and multiply by the
  font size when you draw. Round where your renderer needs it.
* *Move a variable font with `Font.at`.* It is cheap, and every query on the
  result measures at that weight, width or optical size.

The other examples each show one task, and each runs as it is:

[cols="1,3",options="header"]
|===
|Example |What it shows

|`math.roc`
|Read a caller-supplied mathematical font and inspect its layout constants,
larger symbol variants and stretchable glyph recipes. `Font.math_constants`,
`Font.math_kern`, `Font.math_variants` and `Font.math_assembly` return font
facts in font units; the consumer lays out the expression.

|`shape.roc`
|Shape text with `Font.shape` and print each glyph's id, name, cluster (the
text it draws, as a UTF-8 byte offset) and advance; a ligature draws two
characters with one glyph.

|`font-file.roc`
|Read a font file from disk with `Font.from_bytes`, describe each
`Font.Problem` in plain words, and compare lenient reading, `Font.dropped`
and strict reading.

|`weights.roc`
|Measure the same text at Light, Regular, a numeric weight and Bold with
`Font.at`, and list a font's axes.

|`features.roc`
|Turn ligatures off (`liga`, or `calt` for Fira Code's programming
ligatures), use tabular figures (`tnum`), apply small capitals to part of
the text with a byte range, and pick stylistic alternates (`salt`).

|`right-to-left.roc`
|Shape Hebrew right to left: glyphs come in visual order with clusters
counting down, brackets mirror, and a flag marks each character the font
cannot draw, where a program would switch to a fallback font.
|===

Run one from a checkout with `roc examples/shape.roc`. Each release also
attaches `roc-font-examples-<version>.zip`, the same examples naming that
release's bundle, with the output they were tested to print.

[#contribute-to-roc-font]
== Contribute to roc-font

`CONTRIBUTING.md` in the repository says what to install, which compiler to
use and how to run the checks a pull request must pass. The chapters below
explain the design and each kind of test:

* <<roc-font-architecture>> is the design roc-font is moving towards and the
  reasons behind each choice.
* <<conformance-testing-roc-font>> compares roc-font with HarfBuzz, Chrome
  and other references through recorded results.
* <<fuzzing-roc-font>> describes each fuzz target's contract and how a crash
  becomes a permanent regression test.
* <<benchmarking>> covers the timing comparison and the allocation ratchet.
* <<the-default-fonts>> records which fonts roc-font ships, their licences
  and provenance.
* <<variable-fonts-in-roc-font>> scopes variable-font support.
