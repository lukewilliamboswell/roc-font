= The default fonts
:toc: left
:toclevels: 2

This chapter is for contributors. It records which three fonts roc-font
ships as its defaults, why, under what licences, exactly where each file
came from, what is inside them (axes, ligatures, the tables shaping will
need), what they cost, and how to verify or change them. Why the package
ships defaults at all is in architecture §5.8; variable fonts in general are
§5.7.

=== Why these

* *Inter* is the sans most UI and diagram tools already measure with
  (package-mermaid's oracle texts use it), with a wide Latin, Greek and
  Cyrillic repertoire and both a weight and an optical size axis.
* *Merriweather* is a screen-first text serif with weight, width and optical
  size axes and Latin, Cyrillic and Vietnamese coverage. Its 4.x remaster
  is the variable release; the older SorkinType/Merriweather repository is
  superseded (google/fonts now takes Merriweather from
  EbenSorkin/Merriweather4).
* *Fira Code* is the best-known monospaced font with programming
  ligatures, which exercise contextual substitution while keeping every
  advance at exactly one cell (1200 units at every weight).

All three are SIL Open Font License 1.1, ship as one upright variable
TrueType (`glyf`) file each, and have `HVAR`, so advances at any location
can be computed without `gvar`.

The fonts' name tables also carry trademark notices (name ID 7): "Inter UI

Type Co." and "Fira Mono is a trademark of The Mozilla Corporation."

What the OFL allows us to do:

* *Ship the files inside the Roc package.* OFL §1–2: the font software "may
  be bundled, redistributed and/or sold with any software" provided the
  copyright notice and licence go with it, as a separate text file or in
  the font's metadata. We ship each file unmodified with its licence text
  beside it, and expose the text through the API (see "Bundling" below).
* *Reserved Font Names only bind Modified Versions* (OFL §3). Shipping the
  files unmodified, or reading them, does not touch them. Never rewrite,
  subset, instance or rename a shipped file inside the package; a changed
  file named "Merriweather" would breach §3.
* *Embedding in documents* (roc-pdf). OFL-FAQ 1.11–1.12: a font embedded in
  a document, in full or as a subset, is "embedding", and "the restrictions
  regarding font modification and redistribution do not apply". `fsType` is
  0 (installable embedding) in all three, so a strict PDF writer that honours
  `fsType` may embed them. Distributing a subset as a standalone font file
  (for example a webfont) is a Modified Version, and for Merriweather the
  Reserved Font Name then applies.

== Provenance

Every file is pinned in `tools/default-fonts/pins.json` by SHA-256 and size,
with the release archive it came from (pinned by its own SHA-256) and the
archive member, the release commit, and the licence's URL at that commit.
The release archive is the authority, not the repository tree:

Inter::
`InterVariable.ttf` in the release archive
https://github.com/rsms/inter/releases/download/v4.1/Inter-4.1.zip[`Inter-4.1.zip`]
(sha256 `9883fdd4…b11e`); identical to `docs/font-files/InterVariable.ttf`
at commit `e3a3d4c5`. Licence: `LICENSE.txt` in the same archive, identical to
the repository's at that commit. The same file is the conformance corpus
entry `inter-variable-4.1`.

Merriweather::
`Merriweather4-4.009/fonts/variable/Merriweather[opsz,wdth,wght].ttf` in
the release archive
https://github.com/EbenSorkin/Merriweather4/releases/download/4.009/Merriweather4-4.009.zip[`Merriweather4-4.009.zip`]
(sha256 `526473e3…4345`), release commit `e586023a`. The copy committed in
the repository at that commit is a different build (it differs in `GDEF`,
`GPOS`, `GSUB`, `gvar` and `name`) although it also says Version 2.100; the
google/fonts copy differs only in `head.modified`. The version string does
not identify a build; the SHA-256 does. Licence: `OFL.txt` in the archive.

Fira Code::
`variable_ttf/FiraCode-VF.ttf` in the release archive
https://github.com/tonsky/FiraCode/releases/download/6.2/Fira_Code_v6.2.zip[`Fira_Code_v6.2.zip`]
(sha256 `0949915b…3e79`), release commit `eee6db99`. The archive carries no
licence file and the built fonts are not committed, so the licence is
`LICENSE` at the release commit.

Only the upright faces are shipped. Inter, Merriweather and Fira Code
publish italics as separate files (Fira Code has none), which would add
about 5.5 MB; they are not part of the defaults.

Consequences:

* *Substitution does not depend on the location.* No `FeatureVariations`,
  so the same glyphs come out at every location (checked on every example
  below at 3–6 locations each).
* *Advances need `avar` + `HVAR`*; no font needs `gvar` for advances.
* *Kerning needs the `GDEF` item variation store.* Inter's and
  Merriweather's pair kerning values carry `VariationIndex` deltas; without
  them kerning is right only at the default location.
* *Ascent and descent do not vary.* `MVAR` touches no `hhea` or `OS/2`
  ascender/descender value in any of the three.
* *Ink extents need `gvar`.* Only glyph extents (and later outlines) at a
  non-default location do.

The default location is not Regular for two faces: Merriweather and Fira
Code default to Light (`wght` 300). Until variations are supported,
`from_bytes` measures Light for those two. At Regular, Merriweather's
advances change for 2114 of 2384 glyphs (up to 113 units, "Wave To" grows
from 7947 to 8086 units); Fira Code's do not change at all. A browser asked
for `font-weight: normal` draws `wght` 400, not the default.

GSUB lookup type 3 (alternate) only appears under `aalt`, which no default
path applies. Lookup flags in default features: Merriweather's `liga` and
`kern` lookups ignore marks; Inter's `kern` and every face's `mkmk` use mark
filtering sets. They matter only when combining marks sit between the
glyphs; ASCII text is unaffected.

=== Example shaping (HarfBuzz 14.6.0 via uharfbuzz 0.56.3, default features)

Each line gives the text, its glyphs at the default location, and the
total advance at other locations; only the advances change with the
location.

Inter:

* `fi`, `fl`: `[fi=0+1390]`, `[fl=0+1396]`; `wght` 900: 1560, 1543;
  `opsz` 144: 1046, 991
* `ffi`: `[f=0+763|fi=1+1390]` (no `ffi` ligature)
* `office`: `[o|f|fi=2+1373|c=4|e]` = 5276 (kerned); `wdth` 87: 4707

Fira Code:

* `->`: `[hyphen_start.seq=0+1200|greater_hyphen_end.seq=1+1200]`
* `!=`: `[exclam.spacer=0+1200|exclam_equal.liga=1+1200]`

* `www`: `[w.spacer|w.spacer|w_w_w.liga]`, 3600

== What roc-font does with them today

All three are accepted by `Font.from_bytes` with no problem reported. At
the default location, glyph ids, clusters and advances (with pair
kerning) agree exactly with HarfBuzz on the examples above, on mixed
sentences, and on 400 random printable-ASCII strings per face (1256 runs in
all). Not yet supported, and needed for these fonts beyond ASCII or beyond
the default location: `avar`/`HVAR`/`MVAR`/`gvar`, `GDEF` variation deltas
in `GPOS`, GPOS mark attachment (types 4, 5, 6) and lookup flags.

* Evaluating the three reads at compile time took 7 ms (Inter) and 35 ms
  (all three); on a warm cache it is skipped. The LLVM pass, not the read,
  dominates the build.
* Cold peak memory is driven by importing the file, not by reading it:
  importing Merriweather's 4.6 MB costs about 330 MB of compiler memory even
  when it is never read.
* A prepared face holds no font bytes; its binary cost is its prepared
  tables (Inter about 0.33 MB, all three 1.5 MB). Bytes cost their file
  size, and only when the app uses them.
* First use: process start to a shaped width is 0.04 ms over the baseline
  for prepared Inter and 0.14 ms for all three, against 1.3 ms and 6.9 ms
  when the same bytes are read at run time.
* `--opt=dev` and `--opt=interpreter` builds of the three-face app produce
  the same widths.

== Bundling

`roc bundle` includes only files a module imports. A licence text is in the
bundle only if a module imports it (`import "fonts/Inter-OFL.txt" as
inter_licence : Str`), which is also how the API exposes it; an unimported
file in `package/fonts/` is silently left out. The bundle check in
`scripts/all_tests.py` must then accept exactly the files pinned in
`tools/default-fonts/pins.json` and still reject every other font.

`roc build` refuses a dependency whose decompressed size exceeds
`--max-package-mb` (default 10 MB). The package with the three fonts is
about 5.9 MB.

== Measuring with Chrome

The Chrome width oracle can measure a variable font at an explicit location
with a span styled `font-variation-settings` listing *every* axis,
`font-optical-sizing: none` and `font-synthesis: none`. Every axis must be
given: otherwise CSS `font-weight: normal` sets `wght` to 400 and automatic
optical sizing sets `opsz` from the font size. At variable locations Chrome
widths are fractional (exact to 1/64 unit), while HarfBuzz at a scale equal
to units per em rounds each glyph's advance to an integer, so the two agree
within half a unit per glyph rather than exactly. In a scratch run over 174
strings and locations, all agreed within that bound, and every Fira Code
width and most Inter widths agreed exactly.

== Upgrade policy

* *A font change is a breaking change of the package.* Replacing,
  upgrading or adding a default changes measurements and glyph ids, so it
  needs a major version bump and a release note naming the old and new
  versions and SHA-256.
* Upgrade from an upstream *release* (archive or tag), never a branch.
  Record the archive's SHA-256, the member path and the release commit in
  `pins.json`.
* The file stays byte-for-byte as released: no subsetting, instancing,
  renaming, re-hinting or table edits. If a release is unsuitable, choose an
  upstream-provided variant or stay on the old one.
* Before landing: `verify.py --fetch`, `roc check` and the tests, a native
  build of an app using each face, the HarfBuzz agreement check at the
  default location, and these measurements re-run, with this chapter and
  the pins updated in the same commit.

== How to verify

----
python3 tools/default-fonts/verify.py          # committed files match pins.json
python3 tools/default-fonts/verify.py --fetch  # and match the upstream releases
----

The offline check needs nothing but Python. `--fetch` downloads about
50 MB (Inter's release archive is 34 MB), keeps it in memory, and checks
each archive's SHA-256, the archive member and the licence against the
committed files.
