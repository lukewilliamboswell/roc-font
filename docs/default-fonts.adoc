= The default fonts
:toc: left

roc-font ships three families as ten unchanged upstream static TrueType
faces. Every prepared face measures exactly the file its matching bytes
accessor returns. Acquisition and preparation happen before the consumer
runs; no font installation or runtime file access is needed.

== Families and styles

[cols="1,2,2",options="header"]
|===
|Family |Regular and Bold |Genuine italic styles
|Inter 4.1 |`Font.sans`, `Font.sans_bold` |`Font.sans_italic`, `Font.sans_bold_italic`
|Merriweather 4.009 |`Font.serif`, `Font.serif_bold` |`Font.serif_italic`, `Font.serif_bold_italic`
|Fira Code 6.2 |`Font.mono`, `Font.mono_bold` |Unavailable
|===

Append `_bytes` to any face name for its exact file. `Font.sans_licence`,
`Font.serif_licence` and `Font.mono_licence` apply to every style of that
family. Regular is weight 400 and Bold is 700. These files have no variable
axes; optical size and width are the upstream text face's fixed design,
not settings consumers need to resolve. No generated instance, subsetting,
renaming, hinting change or outline modification is performed.

The faces total 7,070,508 bytes. With licences and Roc modules the bundle
must remain below Roc's default 10 MiB uncompressed package limit. Each
face and byte constant is independent; an application need only retain the
ones it uses. The complete default set ships in the main package.

== Coverage and limitations

A character map describes available characters, not a guarantee of correct
shaping for every language. `Font.code_points(face)` lists the full exact
repertoire in increasing order. `Font.glyph` queries an individual code
point. Coverage is per face, including italic faces:

[cols="2,1,1",options="header"]
|===
|Face |Mapped code points |U+2318
|`Font.sans` |2852 |Present
|`Font.sans_bold` |2852 |Present
|`Font.sans_italic` |2816 |Present
|`Font.sans_bold_italic` |2816 |Present
|`Font.serif` |1423 |Absent
|`Font.serif_bold` |1423 |Absent
|`Font.serif_italic` |1422 |Absent
|`Font.serif_bold_italic` |1422 |Absent
|`Font.mono` |1586 |Present
|`Font.mono_bold` |1586 |Present
|===

Upright Merriweather has U+A69C/U+A69D, which its italic lacks; italic has
U+03A0, which upright lacks. Inter italic also has a smaller repertoire
than upright. Do not assume styles cover identical text.

Supported shaping is the package's default shaper and Hebrew shaper;
Arabic joining, Indic and other specialised shapers remain outside the
current supported contract. Mark attachment, cursive and contextual
positioning remain unsupported. Mapping a character does not establish
support for those shaping operations, including decomposed accents.

There is no automatic fallback or synthetic style selection. A strict
consumer uses `Font.shape_checked`, rejects exhausted budgets, then checks
`run.flags` with `Font.is_missing`; `Font.cluster_ranges` locates missing
text. A scalar-only cmap precheck is insufficient because normalisation
and substitutions affect the shaped result. Paragraph segmentation,
script policy and structured document errors belong to the consumer.

Known unsupported requirements and coordination are tracked in
https://github.com/lukewilliamboswell/roc-font/issues/13[issue 13].
Merriweather `⌘` remains explicitly unsupported. Mono italic is unavailable;
see https://github.com/tonsky/FiraCode/issues/134[Fira Code's italic tracker].
No cross-family substitution is implied by either limitation.

== Provenance and licences

`tools/default-fonts/pins.json` records every file's size, SHA-256, upstream
name/version, release commit, archive and member, and licence provenance.
Inter comes from `extras/ttf/` in `Inter-4.1.zip`; Merriweather comes from
`TTF/` in `Meriweather.Static.fonts.TTF.flavor.zip` in release 4.009; Fira
Code comes from `ttf/` in `Fira_Code_v6.2.zip`. The spelling of the serif
archive is upstream's. Merriweather italic reports Version 2.101 while
upright reports Version 2.100; the release and exact digest identify them.

All faces retain their SIL Open Font License 1.1 and copyright notices.
Merriweather retains its Reserved Font Name because files are unchanged.
Its static files also retain their Copyright 2024 metadata notice; the
pinned upstream companion licence carries the Copyright 2020 notice.
See https://openfontlicense.org/ofl-faq/[the official OFL FAQ] for the
distinction between distributing font files and embedding in documents.

----
python3 tools/default-fonts/verify.py
python3 tools/default-fonts/verify.py --fetch
python3 tools/default-fonts/verify.py --install  # reproduce the pinned assets
----

The offline check uses only Python's standard library. Upstream verification
streams each archive once to temporary storage, verifies its complete hash
before comparing members, and removes downloads afterward. The serif
archive is approximately 348 MB; ordinary consumers never download it.

== Migration from variable defaults

This is a breaking asset migration: measurements, glyph ids and metadata
may differ, even at Regular. Upstream static Inter and variable Inter are
not interchangeable builds. Recheck layout and downstream snapshots.

Select `Font.sans_bold` instead of `Font.at(Font.sans, ...)`. `Font.at`
continues to work for caller-supplied variable fonts, but cannot change
these static faces. `Font.axes` and `Font.instances` are empty for them.
The original variable fonts remain test-only fixtures with their existing
conformance witnesses; they never enter the shipped bundle.

== Consumer handoff

For roc-pdf issues
https://github.com/lukewilliamboswell/roc-pdf/issues/69[69] and
https://github.com/lukewilliamboswell/roc-pdf/issues/75[75], use each prepared
face and its matching static bytes, retain its family licence, and validate
the actual selected text/style before returning document bytes. A PDF
writer still owns registration limits, embedding/subsetting, extraction,
rendering and PDF conformance evidence. This API provides static files,
not a runtime sfnt exporter or PDF generation.

Future default upgrades require breaking-change review, exact pins,
upstream verification, cached oracle checkpoints, native consumer tests,
size and build-cost checks, and reviewed downstream layout changes.

== Native build cost

Measured on arm64 macOS with nightly-2026-10-28-bad769b and basic-cli
0.26.0, using the served bundle and native `--opt=speed`. Each app shapes
text received as an argument; the baseline only counts input bytes. Cold
and warm builds use the same per-app `ROC_CACHE_DIR`, initially empty.
Concurrent validation was running, so elapsed figures describe this run
and are not performance thresholds. RSS is the compiler process peak.

[cols="1,1,1,1,1",options="header"]
|===
|Prepared faces used |Cold seconds |Warm seconds |Cold RSS (MiB) |Binary bytes
|none |16.122 |0.518 |548 |2317056
|one |50.555 |7.505 |759 |3084688
|all |50.709 |7.749 |836 |8194176
|===

All three optimised binaries ran successfully at 100, 1000 and 10000 input
characters. The one-face app uses Inter Regular. These apps do not reference
byte constants: prepared faces retain their parsed data, and unused faces
do not enter the application binary. The library allocation ratchet is
checked separately by the benchmark suite.
