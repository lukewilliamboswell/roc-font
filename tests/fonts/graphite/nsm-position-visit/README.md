These 12 original UPL fonts and 72 cases isolate the placement scope of a reverse pass with font-defined NSMs. They use proper Silf 5.0, three full long horizontal metrics (600/601/20), two native directions, and one exact all-A/B matching rule. The action either copies input unchanged or sets only ShiftY to 0 or 17 before COPY_NEXT, RET_ZERO. It never changes X, advances, attachments, insertion or deletion. Independent SFNT checks verify the actual action bytes, matched glyph range, directions and metrics.

Graphite2 1.3.14 public C API results retain authored ShiftY17 on every slot, but after a reverse pass some physical Y positions remain zero. For `ab`, both physical Y positions remain zero in both native directions, despite both authored shifts being 17. For `aab`, native LTR applies Y17 to both A slots and leaves B at zero; native RTL applies Y17 to the first A and B, leaving the second A at zero. Other strings select different subsets. All X positions and segment advances remain identical across the three action variants. A write of Y0 does not restore the normal width.

This makes skipped or suppressed placement a concrete traversal-scope diagnostic. It does not prove the reference's internal mechanism or justify a font-specific workaround. True HarfBuzz 14.6/Graphite2 full runs and raw public-C-API facts remain immutable, with no exception. The native public consumer currently agrees with 36 of 72 cases; the remaining reverse-pass geometry cases remain a failing `verify_all` gate.

All 12 fonts pass pinned OTS 9.3 with Silf, Glat, Gloc and Feat retained identically. `generate.py --check` reproduces their bytes (fontTools 4.61.1); `check.py` validates the raw/HB cache keys and table facts using only the standard library. Raw extraction uses documented public C APIs, not implementation sources. The adjacent license covers these original fixtures.

Eight additional Arabic controls map actual U+0628 BEH and U+064E FATHA to strong RTL and NSM glyphs, respectively, with a native RTL font and a matching requested RTL segment. Both zero and positive mark advances reproduce the reverse-pass zero width and unapplied Y17. This removes an ASCII/script mismatch or opposite-direction explanation. Their raw/HB caches are separate and unchanged by the original 72-case audit. The checker decodes the BMP cmap independently.
