This corpus exercises AAT positioning through the public package bundle. Original fixtures cover kerx formats 0/1/2/4/6, Apple kern formats 0/1/2/3, older kern formats 0/1/2/3, kerx versions 2/3/4, tuple vectors, direction, cross-stream and stateful adjustments, feature disabling, GPOS precedence, empty tables and TrueType contour/anchor attachments. Generated fonts use `SYNTHETIC-LICENSE.txt` (UPL 1.0); regenerate with fontTools 4.61.1 using `generate.py`.

`Jellee-Roman.ttf` is copied unmodified from HarfBuzz 14.6.0 in-house font `e39391c77a6321c2ac7a2d644de0396470cd4bfe.ttf`. It contains actual Apple kern 1 format 0 and two format 2 subtables. Its embedded full OFL 1.1, copyright Alfredo Marco Pradil 2016 with Reserved Font Name Jellee Roman, is preserved in `Jellee-OFL.txt`. [Pinned source](https://github.com/harfbuzz/harfbuzz/blob/14.6.0/test/shape/data/in-house/fonts/e39391c77a6321c2ac7a2d644de0396470cd4bfe.ttf).

`oracle.py` records actual HarfBuzz 14.6.0 outputs in JSONC. `verify.py` builds the optimized Roc consumer from a source-sentinel mirror using the served `roc bundle` artifact, then replays the cache without installed oracle libraries. `tests/api/AatPositionTests.roc` tests public malformed/empty/default policies. OTS 9.3's default policy discards kerx/ankr and Apple kern rather than validating their positioning programs; `ots.json` records the discarded tags explicitly. OTS output must not be called evidence of AAT-table validity.

Control-point provenance matters: HB 14.6's default OpenType font-functions backend leaves its contour-point callback unimplemented (`hb-ot-font.cc`, line 991). The kerx4 point cases therefore use HB 14.6 shaping with an explicitly registered FreeType 2.13.2 unhinted, unscaled contour-point callback. Every other glyph-mapping, metrics and shaping function remains HarfBuzz's OpenType implementation. `point_oracle.py` implements that configuration, and the cache preserves the default-OT backend's output separately. The variable point witness changes contour coordinates and the left phantom simultaneously; the capable reference and Roc must agree on both moved advance and moved attachment. [OT source](https://github.com/harfbuzz/harfbuzz/blob/14.6.0/src/hb-ot-font.cc), [FreeType callback source](https://github.com/harfbuzz/harfbuzz/blob/14.6.0/src/hb-ft.cc).

Reference rules pinned by this track:

- kerx tuple vectors are checked to their declared tuple count, but pinned HB takes only the first FWORD. Legacy Apple Variation subtables are skipped. This is not OpenType axis interpolation.
- kerx1 state action indices are byte offsets, even though the format field name calls them indices. Its stack has 8 slots; overflow resets the stack. Values pop in LIFO order, their low termination bit is cleared, and a non-cross-stream adjustment changes both advance and offset.
- kerx4 actions precede updating the marked glyph. Point lookup failure aborts that action. Anchor lookup preserves explicit absence. Apple's ankr specification defines no zero-coordinate fallback for a missing glyph or out-of-range point: Roc aborts the invalid dynamic attachment instead of copying HB's defensive Null(Anchor). No missing reference selects a different glyph or point.
- The first applicable cross-stream subtable initializes cursive links. Kerning may reset them with −32768. Cursive finish propagates parent cross offsets; mark finish propagates only the flow-axis parent offset and then accounts for advances in reference saturation order. Shared attachment finish retains its 64-frame nesting cap and signed 16-bit links.
- Even an empty, valid kerx table selects the AAT positioning provider and affects mark-zeroing policy. Empty older kern 0 differs because HB's table-presence test reads its zero version/count header.
- Reserved coverage bits and malformed search selectors reject the optional table; lenient mode reports and drops it, strict mode rejects the font. Redundant searchRange/rangeShift fields remain unused by the independent binary search and are never rewritten.
