# Kerning-frame history and attachment drawing

These 55 original UPL fonts use documented GTF/OpCodes structures and original synthetic geometry. Reference data come only from Graphite2 1.3.14's public C API and `gr_start_logging`; no implementation source was read or translated. A full-size subbox on unused glyph 0 neutralizes the separate preload geometry issue. All 55 raw mode-0/mode-6 pairs match bit for bit.

Whole vertical bounds in the trace accumulate over already-visited logical slots, including non-KERN, non-FIX and IGNORE slots. A tall middle slot expands a later target's frame even when the first target was small; a future tall slot does not expand earlier frames. An empty outline or point at (0, 0) seeds zero bounds before a raised target. A second pass discards earlier extrema: after an original rule moves the first slot upward 3000 units, a later frame retains the newly visited height but drops the previous pass's minimum.

This is not merely a trace-header observation. With flags [0,17,0], current target Y 0..600, margin 10 and a thin neighbor Y 303..307, changing only the preceding slot's minimum from 0 to -603 changes the public segment advance from 508 to 510. A minimum of -607 gives 508.3333435058594. The preceding slot is behind the target and has no KERN flag. Thus sampling history affects completed output.

Occupied target bounds must be distinguished from the displayed frame. A prior tall slot gives current-small-whole frame [-610,1210], but actual finite target bins are 91..182, not the global-maximum cap 272. The minimum selects the sampling grid; the displayed maximum does not itself cap every shape drawn into it.

Attached children demonstrate the distinction further. A left-extending child dominates target ink for flags 0, 1, 17, 2. Child-before-parent expands the displayed frame; child-after-parent does not, although its ink still contributes. For the latter arrangement the displayed parent frame is [-10,610], while child-part upper byte 128 occupies through bin 74, byte 160 through 108 and full 255 through 139 (the allocated vector ends at 139). Root-whole cap 92 therefore does not cap a child's part. These are measured boundaries, not a claim that the complete attachment/cache algorithm has been derived.

The corpus preserves both native directions for a prior-tall control, first/middle/future flags, child logical relations, a pass-reset program, blank/point seeds, public-output sampling discriminators and child-part upper bounds. It adds no runtime rule, generated Roc expected source, tolerance or deliberate exception.

Run `python tests/fonts/graphite-geometry/kern-frame-audit/check.py` from the repository root. It reproduces fonts/cases, verifies all immutable cache keys and both-mode equality, and checks the independent public output and trace relations without loading an oracle. Raw records retain exact binary32 bits, authored advances, attachment links and collision attributes. Traces retain normalized public logging. Reference library versions and hashes are cached; generation used fontTools 4.61.1.

The follow-up preserves capacity threshold/margin/translation controls. The observational count model `trunc(F32(F32(F32((displayMaxY-displayMinY+2)/w)*1.5)+1))` fits these records and 55 independent temporary challenges. Exact binary32 association alternatives remain unseparated. Drawing tall/full child geometry does not grow the vector in these controls.

Lower bounds distinguish whole geometry from expanded actual parts: the whole lower index is `max(0,floor((wholeMin-frameMin+1)/w))`; a part's expanded lower index is additionally bounded by that whole lower index. Future children at Y=-7/-2/3 and subbox lower bytes 13/64 pin bins 0/1/2 and the part boundary separately. These observations reject an unconditional minimum index 1.

Near-negative upper bounds require care: child wholeMax=-18/-12 contributes bin 0, while -11 contributes 0 and 1. Far below the frame (-25/-1000), both whole and actual partial geometry contribute no cells. The observations fit a whole upper cap clamped at 0, intersected with a SIGNED margin-expanded rendered upper bound that may still make the interval empty. They do not justify clamping the final rendered upper endpoint to 0. Cached raw answers and trace cell lists remain authoritative.

`ots-proof.json` records acceptance of all 55 original fonts by pinned OTS 9.3.0, including the sanitizer binary and font hashes. This checks font structure; the cached Graphite references check shaping behavior separately.

The native-LTR prior-offset promotion pair first creates collision Y = +600 on the parent through an actual FIX shift, with X limits [-1,1] and Y limits [-1000,1000]. The next original rule attaches a preceding child and selects child flags 0 or 17. Without promotion final parent/child Y positions are 600/770. With child flags 17 the parent flags become 81 and final Y positions become 0/170, while its stored collisionY remains 600. Yet the kerning trace uses target origin [0,600], previous offset [0,600] and frame [590,1380]. This pins pre-promotion physical geometry for that kernel operation separately from final native-LTR offset suppression. It rejects eagerly recomputing each visited slot's physical position after promotion. Both second passes use flags 9; this preserves valid public JSON logging and the no-promotion/promotion final outputs observed independently with flags 8.

The unrestricted prior-Y pair exposes a second-pass SHIFT disagreement. Original first-pass-only controls agree at +600 in both engines; disabling only the second collision pass also preserves +600. The complete second pass makes the earlier Roc snapshot end at -600. The positive-Y pair forces the initial shift into [600,1000], separating that precondition from the later disagreement. The attachment-lifetime audit preserves both timing cases and counterexamples to a generic descendant filter. The original answers remain unchanged.

A downstream public-output discriminator avoids relying on logged intermediate coordinates. After child KERN promotion, another future child D of the same parent ends at physical Y 170. A downstream target C has bbox Y 1000..1600 and wide X limits. The reference still gives C advance 320 from its overlap with D's earlier physical Y 770; a control with D unattached below C gives advance 1100. Both promoted and unpromoted variants preserve these answers. Refreshing the promoted parent's attachment positions during the kerning scan would remove that overlap and change the completed output.

Instrumentation is checked explicitly: `tracing-off-records.json` and `tracing-on-records.json` use the SAME hash-pinned tracing library with logging disabled/enabled. All 55 final public results match exactly, including every slot's position/advance bits, collision attributes and attachment links. Both also equal the release-library mode-6 records. This is a local instrumentation-neutrality proof, not a blanket claim about Graphite logging (the independent NSM corpus demonstrates logging-sensitive positioning).
